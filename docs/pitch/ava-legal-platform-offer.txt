2. THE PLATFORM — COMPLETE INVENTORY
==================================================================

2.1 PRACTICE MANAGEMENT CORE
  - Digital matter files (Akten) with full lifecycle: intake,
    conflict-of-interest check, parties, opposing parties, notes,
    documents, deadlines, billing — multi-tenant from the ground up.
  - Deadline engine where all rules are DATA, not code: ZPO, ArbGG,
    VwGO deadline rules and German court holidays ship as seed data;
    new rules are added without touching program logic.
  - Calendar with deadlines, hearings and appointments; ICS feeds.
  - Template system with variables, per-jurisdiction template packs,
    document generation to DOCX/PDF.
  - Full-text search across matters, contacts, documents and the
    legal corpus, with fuzzy matching and a Cmd+K command palette.
  - Contact/client management with legal-entity support.
  - Audit trail: every user-visible action on matters and documents
    is logged immutably per tenant.

2.2 GERMAN LEGAL COMPLIANCE, BUILT IN
  - RVG fee calculation (Verfahrens-/Termins-/Einigungsgebuehr,
    Anrechnung, tables as data) and a public Prozesskostenrechner.
  - E-invoicing: ZUGFeRD 2.x and XRechnung generation, DATEV export.
  - Mahnwesen: dunning runs, interest calculation, and EDA file
    export for the automated court Mahnverfahren (structure
    validated against the public specification; marked Beta until
    first live submission to a Mahngericht).
  - Rechtsschutzversicherung workflows: coverage request (Deckungs-
    anfrage) drafting and tracking per matter.
  - Structured intake questionnaires per legal area (family, labor,
    tenancy, traffic, inheritance, ...) collected identically via
    web, WhatsApp and telephone.
  - Pseudonymization layer: names, emails, phone numbers, IBANs and
    national IDs are replaced with stable placeholders BEFORE any
    prompt leaves the server for an external AI provider, and
    restored transparently in the response — including in streamed
    responses. Client data never reaches an external model in clear.
  - Local embeddings (sentence-transformers) for all document and
    corpus indexing: document text never leaves the machine for
    indexing purposes.
  - Documents encrypted at rest; per-tenant isolation; append-only
    database migration history (52 migrations).

2.3 THE AI LAYER
  - Assistant grounded (RAG) in an indexed corpus of German federal
    law and 16,000+ published court decisions, growing every night
    via automated imports (Bundesgerichte + openlegaldata pipeline);
    hybrid retrieval (semantic + full-text, reciprocal rank fusion).
  - Automatic citation verification: every statute and case number
    the AI cites is checked against the corpus and badged as
    verified/unverified in the UI — the answer earns trust, not
    just fluency.
  - Agentic execution: the assistant plans multi-step actions
    (create deadline, draft document, schedule appointment) with a
    visible step plan and explicit lawyer approval before anything
    is executed.
  - Proactive AI: morning briefing per lawyer (optionally spoken,
    local TTS), overnight monitoring of new case law relevant to
    open matters, automatic deadline audits.
  - Deep research mode with structured legal analysis.
  - AI e-mail classification and deadline extraction from documents
    (suggested deadlines with lawyer confirmation).
  - LLM-agnostic architecture: one abstraction serves DeepSeek,
    any OpenAI-compatible API, or a fully LOCAL model (validated on
    our own GPU infrastructure with gemma3:27b via Ollama). Task-
    based routing and automatic fallback are built in. A hard
    "local-pinned" mode guarantees that privacy-sensitive tenants
    never touch an external model.
  - Local speech stack: Whisper (STT) and Piper (TTS) run on the
    server — voice never leaves the machine. Used for dictation,
    spoken briefings, voice conversation mode and telephony.

2.4 CLIENT ACQUISITION — THE 24/7 FRONT DOOR
  - Public citizen portal: legal guides (Ratgeber), cost calculator,
    court-fee calculator, public AI chat with the same corpus
    grounding and citation verification as the lawyer-side AI.
  - Structured case intake: citizens describe their problem, the AI
    classifies the legal area, asks the field-specific questions a
    lawyer would ask, and delivers a structured case request.
  - WhatsApp intake: the full intake conversation, including
    category-specific questionnaires and appointment scheduling,
    runs over WhatsApp in the citizen's language.
  - Telephone AI receptionist: Asterisk + SIP trunk (e.g. sipgate),
    local STT/TTS, conversational intake that creates a structured
    case request from a phone call — 24/7, no staff.
  - Client portal for ongoing matters: status, documents, messages.
  - Online appointment booking.

2.5 SWITCHING TOOLS — BUILT TO BEAT LOCK-IN
  - 4-step data migration wizard: CSV/XLSX import with column-
    mapping presets for RA-MICRO and Advoware exports, dry-run
    preview, opposing parties, legacy Aktenzeichen (searchable),
    and bulk document import via ZIP with automatic matter
    assignment.
  - Outlook add-in: "save e-mail to matter" (message + attachments)
    directly from the Outlook taskpane, wired into the normal
    document pipeline and audit trail.
  - 7 interface languages (DE, EN, SQ, TR, SR, BS, ZH) — relevant
    for firms with international clientele.

2.6 TECHNICAL FOUNDATION
  - Stack: Python 3 / FastAPI / SQLAlchemy 2 (async) / PostgreSQL 17
    with pgvector / Redis / Next.js + TypeScript + Tailwind.
  - Scale: ~76,000 lines of production code, 287 API endpoints,
    314 automated tests, 52 append-only DB migrations.
  - Multi-tenant architecture; per-country jurisdiction profiles —
    every jurisdiction (deadline rules, holidays, templates, fees,
    corpus) is data, not code. Expansion to Austria or Switzerland
    is configuration plus corpus import, not a rewrite.
  - Self-hosted observability: error tracking (GlitchTip/Sentry-
    compatible) and privacy-friendly analytics (Umami).
  - Passkey (WebAuthn) login, Google OAuth, dark mode, PWA install,
    skeleton loading states — current-generation UX throughout.
  - Clean dependency licensing (no copyleft contamination), built
    for due diligence from day one.

2.7 HONEST STATUS OF OPEN ITEMS
  - beA integration: not yet implemented (requires beA card and
    certification process). The architecture has a clear slot for
    it; under Options 2-4 it is the first roadmap item.
  - Local LLM legal fine-tuning: the local model runs in production
    quality today; a German-legal fine-tune is specified as the
    next step and is included in the development agreements below.
  - EDA/Mahnverfahren: structure validated against the public spec,
    Beta until the first live court submission.
